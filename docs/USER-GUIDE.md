## 0. 开始之前

### 0.1 你需要准备

| 项目 | 说明 |
| --- | --- |
| 一个产品 | 名称、规格、认证、产能、MOQ、交期（**至少填真实信息**） |
| 一个目标客户画像 | 国家/地区、企业类型、规模、采购角色、关键词 |
| 一个发件邮箱 | 企业邮箱的 SMTP/IMAP 信息（或先用"模拟邮箱"体验） |
| 合规信息 | 发件公司名、地址、隐私政策链接（欧洲营销必需） |
| （可选）AI 模型 Key | DeepSeek 或其他 OpenAI 兼容端点；不填则使用内置模拟模型 |

### 0.2 三条铁律

1. **只能写真实信息**：产品认证、产能、价格、客户案例不得编造；AI 被约束为"只能引用你录入的事实"。
2. **默认人工审批**：每封外发邮件都要你点"通过"，系统不会自动群发。
3. **接管即停**：你把客户转为"人工接管"后，AI 不再自动回复或跟进。

## 1. 首次初始化

1. 浏览器打开系统地址（默认 **http://127.0.0.1:4173**）。
2. 首次访问自动进入**初始化向导**，填写：
   - **工作空间名称**（如"智睿外贸一部"）
   - **你的姓名**
   - **登录邮箱**
   - **密码**：至少 10 位，必须同时包含字母和数字
3. 提交后自动登录，进入「全局总览」。
4. 建议立即完成：
   - 右上角用户菜单 →「修改密码」（如使用初始密码）
   - 「系统设置」→ 合规信息（发件公司名/地址/隐私政策 URL）
   - 「系统设置」→ AI（选择模型；默认模拟可先体验）
   - 「系统设置」→ 邮箱账户（添加发件邮箱）

> 初始化只允许一次；系统已有用户后，`/api/v1/auth/setup` 会返回"系统已经初始化"。

## 3. 工作空间、成员与角色

### 3.1 角色

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| **拥有者 owner** | 全部权限；备份、删除工作空间、删除抑制记录 | — |
| **管理员 admin** | 管理设置、成员、凭据、邮箱账户、审批、发送、接管 | 不能删除工作空间、不能移除 owner |
| **成员 member** | 业务数据读写、评分、发现、草稿、审批、发送、接管、导入导出 | 不能改设置/成员/凭据、不能删除数据 |
| **只读 viewer** | 查看业务数据、任务状态 | 不能写任何数据 |

### 3.2 添加成员

1. 「系统设置」→ 成员管理 → 添加成员。
2. 填邮箱、姓名、角色、初始密码（新用户必须设密码，≥10 位且含字母数字）。
3. 新用户首次登录会被强制修改密码。
4. 移除成员会自动吊销其会话。
5. **每位成员使用独立账号**；不要共享账号（审计需要可追责）。

### 3.3 账号安全

- 用户菜单 →「修改密码」：修改后所有会话失效，需重新登录。
- 用户菜单 →「API 密钥」：用于自动化调用；**明文只显示一次**，请立即保存；可吊销。
- 会话安全：移除/停用成员会自动吊销其会话；如需查看或吊销自己的其他会话，使用 `/api/v1/auth/sessions`（见 [API.md](./API.md) §7.7）。

## 4. 产品资料

### 4.1 录入什么

「产品资料」→ 新建产品：

| 字段 | 说明 | 对 AI 的影响 |
| --- | --- | --- |
| 产品名称 | 如"新能源汽车电池包支架" | 开发信主题/正文引用 |
| 分类 / SKU | 便于筛选 | 匹配 |
| 规格 `specs` | 材料、尺寸、工艺等（JSON 对象） | 产品匹配与技术问题回答 |
| 应用领域 `applications` | 适配车型/场景 | 匹配理由 |
| 材料 / 认证 `certifications` | 如 IATF 16949、ISO 9001 | **只有这里写了的认证，AI 才能提** |
| 产能 / MOQ / 报价条件 / 样品 / 交期 | 商务事实 | 报价类回复的参考 |
| 状态 | active / draft / archived | 归档产品不参与推荐 |

### 4.2 重要提醒

- **没填的字段不要靠 AI 补**：AI 被明确约束"不得编造认证、产能、价格、客户案例、供应能力"。
- 认证名称请写完整、准确（写错比不写更危险）。
- 产品文件（图纸/目录）可在产品详情上传，存放在 `DATA_DIR/uploads`。

## 5. 客户画像（ICP）

「客户画像」→ 新建 ICP：

| 字段 | 示例 | 作用 |
| --- | --- | --- |
| 名称 | 德国汽配进口商 | 便于活动引用 |
| 关联产品 | 电池包支架 | 评分与匹配的产品基准 |
| 目标国家 `targetCountries` | `DE`, `FR`, `NL` | 地区匹配分 |
| 目标区域 `targetRegions` | `Bavaria`, `North Rhine-Westphalia` | 细分筛选 |
| 目标企业类型 `targetCompanyTypes` | `importer`, `distributor`, `wholesaler`, `aftermarket` | 企业类型匹配分 |
| 目标规模 `targetSizes` | `50-200`, `200-1000` | 规模匹配 |
| 目标角色 `targetRoles` | `purchasing`, `procurement`, `technical` | 联系人研究 |
| 包含关键词 `includeKeywords` | `battery`, `EV`, `aftermarket` | 加分/筛选 |
| 排除关键词 `excludeKeywords` | `recruiting`, `job`, `blog` | 排除非目标 |
| 最低评分 `minScore` | 60 | 低于该分不进入推荐 |

> ICP 不是"越宽越好"。宽 ICP 会拉低线索质量；建议按"产品 × 国家 × 企业类型"拆分多个 ICP。

## 6. 企业发现

### 6.1 发起发现

「企业发现」→ 新建发现批次：

1. 选择**数据源（Provider）**：
   - **内置模拟数据源**：离线、免费，用于演练完整流程；
   - **CSV / 表格导入**：用你已有的企业名单（最可靠）；
   - **公开网站抓取 / 可配置搜索 API**：需配置与凭据，按页面显示的可用来选择（`implemented` 状态以页面为准）。
2. 填关键词、国家、企业类型、行业、地区、数量上限。
3. 提交后生成**发现批次**，后台任务入队执行。
4. 在批次列表查看状态（`queued/running/completed/failed/cancelled`）、结果数、新建企业数、错误信息。

### 6.2 发现结果去哪了

- 新建企业进入「潜在客户」，并在 `company_sources` 记录来源（类型、URL、抓取时间、置信度）。
- **未经验证的信息不会标记为事实**：企业可信度默认为 `unverified`。

### 6.3 取消与重试

- 批次可取消（`/discovery/runs/:id/cancel`）。
- 失败任务可在「任务队列」里重试（仅失败/取消/死信可重试）。

## 7. 潜在客户与联系人

### 7.1 企业列表（潜在客户）

- 支持搜索（名称/域名/描述）、国家、状态、评分区间、是否有邮箱、ICP、产品、负责人、标签、自动化状态筛选。
- 排序：名称、创建/更新时间、国家、状态、评分、数据质量、联系人数。
- 批量操作：评分、归档、分配负责人、改状态。
- 右上角可「导入 CSV」「导出 CSV」「新建企业」。

### 7.2 企业详情

聚合展示：企业信息、联系人、来源、校验记录、产品匹配、评分历史、自动化状态、邮件线程、草稿、商机、活动、跟进任务、时间线、统计。

常用动作：
- **评分**：选择产品 → 生成可解释评分；
- **补全（enrich）**：补联系人/推断邮箱；
- **抓取官网（crawl）**：抓取公开页面并抽取信息（可指定 1–5 个 URL）；
- **新增联系人**；
- **查看来源/校验**：确认每条信息从哪来。

### 7.3 联系人

「联系人库」→ 列表（按公司、邮箱状态、角色、国家筛选）。
- **验证邮箱**：语法 + MX 查询；结果写 `data_verifications` 并更新 `email_status`。
- **推断邮箱**：根据企业域名与姓名生成候选，**状态一律为 `inferred`**，不得当作已验证。
- **角色分类**：决策者 / 影响者 / 把关人 / 技术 / 未知 —— 用于决定先联系谁。
- **主联系人**：每家企业建议设 1 位主联系人。

> 邮箱类型：`business`（企业邮箱）、`role`（如 info@/sales@）、`personal`、`inferred`（推测）、`unknown`。

## 8. 评分与匹配原因

### 8.1 评分怎么看

评分是 **0–100** 的规则分（`rules-v1`），等级 A/B/C/D：

| 因素 | 权重（示例） | 说明 |
| --- | --- | --- |
| 产品匹配度 | 25% | 企业业务与产品是否相关 |
| 企业类型匹配 | 10% | 是否 ICP 目标类型（进口商/分销商…） |
| 目标地区 | 15% | 国家/地区是否匹配 |
| 采购场景 | 15% | 采购/分销/售后关键词 |
| 信息可信度 | 10% | 企业信息完整度与验证状态 |
| 联系方式可信度 | 15% | 是否有邮箱、是否验证 |
| 近期信号 | 10% | 近期沟通/采购信号 |

界面会显示**每项的原因（reason）与证据（evidence）**，以及**排除项**（如命中排除关键词）。评分可追溯到具体因素，不是黑箱。

### 8.2 人工修正

对 AI/规则的判断不满意时，可提交反馈（字段、AI 值、你的值、原因）。反馈会记录在 `score_feedback`，作为规则迭代依据——**系统不会承诺"自动越用越准"**。

### 8.3 评分使用建议

- 先用 ICP 的 `minScore` 过滤，再人工抽查高分企业。
- 低分不一定是坏客户，可能是数据缺失（补全后再评分）。
- 对"排除项"要敏感：命中排除词的客户通常不值得跟进。

## 9. 销售活动（Campaign）

### 9.1 创建活动

「邮件草稿」/「统一收件」空状态按钮「去创建活动」（或 `#/campaigns`）→ 新建活动。字段：
- 名称、关联产品、关联 ICP、目标（goal）、状态（draft/active/paused/archived）
- 日限额 `dailyLimit`（默认 30）、是否需要审批 `requireApproval`（默认是）
- 发送窗口继承工作空间设置（默认 Europe/Berlin 9–17 工作日）

### 9.2 步骤（Steps）

每个活动可有多个步骤（`stepNo` 唯一）：
- 主题模板、正文模板、语言、延迟天数、启用状态。
- 模板变量如 `{{company}}`、`{{first_name}}` —— **发送前必须有值**，不能用空变量发出去。

### 9.3 入组（Enroll）

- 选择企业/联系人加入活动；返回 `enrolled/skipped/duplicate/noEmail/suppressed/automationBlocked/invalid` 计数。
- **被抑制、被接管/禁止联系、无邮箱、重复** 的联系人会被自动跳过（这是安全设计，不是 bug）。

### 9.4 激活与暂停

- **活动必须 `active` 才能发送**（否则发送草稿会报"活动未启用"）。
- 暂停（pause）/恢复（resume）只影响活动推进，不解除客户的接管/退订状态。

### 9.5 统计

查看目标数、已发送、已回复、退订、待审批、完成、退回、回复率、退订率。

> 建议：新活动先小批量（如日限额 5–10）跑 3–5 天，观察退信与回复，再逐步提高。

## 10. 邮件草稿生成

### 10.1 两种方式

1. **手动创建**：选企业 + 联系人（可关联活动），自己写主题与正文。
2. **AI 生成**：创建草稿后点「生成」→ 服务端调用 Agent（默认模拟模型）→ 返回 `pending_approval` 草稿。

### 10.2 AI 生成会做什么

- 读取：企业公开信息、联系人、产品资料、ICP、语言。
- 生成：主题 + 正文（按语言）。
- 约束：**只引用输入中的事实**；不编造认证/产能/价格/案例；正文通常包含退订提示。
- 记录：每次生成写 `agent_executions` 与 `usage_records`（token、成本估算、耗时），草稿可追溯。

### 10.3 生成后必须人工检查

- 事实是否准确（认证、产能、价格）；
- 语言是否得体（尤其德语/法语商务礼仪）；
- 变量是否都已替换（公司名、姓名）；
- 退订方式是否清晰；
- 是否与收件人业务真正相关（不要发给无关企业）。

> 模拟模型只用于演练，**内容不代表真实质量**；正式使用请配置真实模型并逐封审阅。

## 11. 发送审批与发送

### 11.1 审批流程

`草稿 → 待审批（pending_approval）→ 通过（approved）→ 发送（sent）`

「发送审批」页面：
- 查看待审批草稿（可按活动/关键词筛选）；
- 逐封**通过 / 驳回（填原因）**；
- **批量通过**（仍建议抽查内容）；
- 通过后可发送（单封或批量）。

### 11.2 发送前系统会检查（五道闸）

1. 草稿已审批；
2. 邮箱/域名不在抑制名单（退订/投诉/拒联）；
3. 客户自动化状态不是 `HUMAN_TAKEOVER / DO_NOT_CONTACT / PAUSED / CLOSED`；
4. 未全局暂停发送；
5. 在发送窗口内、未超账号/工作空间日限额、非重复发送、未触发退信熔断。

任一不通过：**不会发送**，并在任务/草稿上留下原因（可在「任务队列」查看 `lastError`）。

### 11.3 发送失败常见原因

| 提示/现象 | 原因 | 处理 |
| --- | --- | --- |
| 活动未启用，不能发送 | 活动仍是 `draft` | 把活动改为 `active` |
| 未审批 | 草稿状态不是 `approved` | 先去审批 |
| 已退订/拒联 | 命中抑制名单 | 不要发送；尊重对方意愿 |
| 接管中/暂停/关闭 | 自动化状态禁止 | 恢复自动化或人工处理 |
| 窗口外 | 不在 Europe/Berlin 9–17 工作日 | 等待窗口或调整设置（不建议随意放宽） |
| 超限额 | 日限额用尽 | 次日再发或调整限额 |
| 重复发送 | 同一联系人已发过 | 检查线程，不要重复骚扰 |

### 11.4 自动发送（谨慎）

- 默认关闭（`autoSendEnabled=false`、`requireApproval=true`）。
- 如确需开启：必须由 admin/owner 在设置中显式开启，并同时设置**低日限额 + 发送窗口 + 退信熔断**；首次建议仅对高置信度线索开启。
- 即使开启自动发送，**接管/退订/抑制检查仍然生效**。

## 12. 统一收件与回复分类

### 12.1 收件箱

「统一收件」：
- 线程列表：未读、高意向、公司、分类、状态、搜索；
- 线程详情：完整邮件对话、关联企业与联系人、AI 分类结果、建议回复；
- 手动回复（人工发送，不走 AI 自动回复）；
- 标记已读。

### 12.2 回复分类（11 类）

`positive_interest`（正面意向）、`price_inquiry`（询价）、`quote_request`（索报价）、`sample_request`（索样）、`technical_question`（技术问题）、`follow_up_needed`（需进一步联系）、`no_need_now`（暂不需要）、`rejection`（拒绝）、`unsubscribe`（退订）、`auto_reply`（自动回复）、`unknown`（无法判断）。

每条分类保存：置信度、意向分、证据片段（原文引用）、理由、建议回复、执行记录 ID。
- **不会因为一个正面词就判定成交**；
- 分类可由你手工修正（`user_corrected`），用于统计与后续优化。

### 12.3 高意向提醒

高意向（询价/索报价/索样/明确正面）会进入通知中心（铃铛）与「收件箱 → 高意向」，建议**当天**处理。

### 12.4 退订/拒绝

- 对方说"不要再发/退订" → 系统应写入抑制名单并置 `DO_NOT_CONTACT`；如果你手工发现，请到「自动化流 → 抑制名单」添加，或直接对该客户执行「禁止联系」。
- **退订后不得再用任何方式联系**（包括换邮箱、换人）。

## 13. 真人接管

### 13.1 什么时候接管

- 客户回复高意向，需要真人谈判；
- 客户提出技术/商务问题，AI 无法可靠回答；
- 客户语气不满、要求停止；
- 你准备亲自打电话/见面。

### 13.2 怎么接管

「自动化流」→ 找到客户 → **接管**（填原因）→ 或从企业详情/收件箱线程执行。

接管会一次性完成：
1. 状态改为 `HUMAN_TAKEOVER`；
2. 取消该客户未发送的跟进任务；
3. 取消该客户的后台任务；
4. 写审计记录；
5. 保留全部历史邮件、分类与草稿（不会删除）。

接管后：**AI 不再自动回复/跟进**；界面显示"人工接管中"，发送被拒绝。

### 13.3 恢复自动化

- 从「自动化流」选择客户 → **恢复自动化**（需填原因）；
- 只允许从 `HUMAN_TAKEOVER / PAUSED / NEEDS_HUMAN_REVIEW` 恢复；
- **`DO_NOT_CONTACT` 不能通过"恢复"按钮解除**：必须先由 admin/owner 删除对应抑制记录（并承担合规责任）。

### 13.4 其他状态

| 状态 | 含义 | 谁能改 |
| --- | --- | --- |
| `AUTOMATION_ACTIVE` | 允许自动流程 | 系统/成员 |
| `NEEDS_HUMAN_REVIEW` | 需要人工看一眼 | 成员确认后继续或接管 |
| `PAUSED` | 暂停 | 成员 |
| `HUMAN_TAKEOVER` | 人工接管 | 成员恢复 |
| `DO_NOT_CONTACT` | 禁止联系（退订/投诉/GDPR） | 仅 admin/owner 删除抑制记录 |
| `CLOSED` | 已关闭（成交/放弃） | 成员 |

## 15. 自动化流与抑制名单

### 15.1 自动化流

- 查看所有客户的自动化状态、原因、变更时间；
- 执行：接管 / 恢复 / 暂停 / 禁止联系 / 关闭；

- 删除抑制记录 = 允许再次联系，请谨慎并留审计。

4. 未配置或不可达时回落内置模拟模型（不阻断流程，但内容质量不同）。

## 19. 备份与恢复

### 19.1 备份

- 维护台 `/admin` →「创建备份」（owner），或 `npm run backup`；
- 生成 `server/data/backups/outreach-<时间戳>.sqlite`；
- 用 `VACUUM INTO` 热备，不需要停机。

### 19.2 恢复

1. 停止服务；
2. 备份当前数据库（以防恢复错）；
3. 删除 `outreach.sqlite-wal` 与 `outreach.sqlite-shm`；
4. 用备份文件替换 `outreach.sqlite`；
5. 启动并验证（登录、企业数、最近邮件、设置）。

> `secret.key` 丢失会导致已存凭据无法解密（需重新录入）；请与数据库备份分开安全保存。完整步骤见 [DEPLOY.md](../DEPLOY.md) §8。

## 20. 每日推荐工作流

**早上（15 分钟）**
1. 打开「全局总览」看警报与待办；
2. 「统一收件」处理未读与高意向；
3. 「发送审批」批量审阅昨天的草稿（先抽查 3–5 封再批量通过）。

**上午（30–60 分钟）**
4. 补充/更新产品与 ICP（有新品时）；
5. 跑一次发现或导入一批新企业；
6. 给高分企业评分、补全、生成草稿。

**下午（30 分钟）**
7. 处理回复：分类修正、人工回复、必要时接管；
8. 推进商机与跟进任务；
9. 检查「任务队列」是否有失败任务；
10. 结束前创建一次备份。

**每周**
- 检查用量与成本；
- 审查退订/投诉/退信；
- 清理长期无互动联系人（按保留策略）；
- 回顾 ICP 与评分阈值，微调规则（记录原因）。

## 21. 常见问题

**Q1：为什么草稿发送按钮点了没反应/报错？**
按顺序检查：草稿是否已审批 → 活动是否 `active` → 是否命中抑制名单 → 客户是否被接管/暂停/关闭 → 是否在发送窗口 → 是否超日限额 → 是否重复发送。

**Q2：为什么活动入组时有些人被跳过？**
可能原因：无邮箱、重复、命中抑制名单、客户处于禁止联系/接管状态。这是安全设计。

**Q3：AI 写的开发信能直接发吗？**
不能。默认必须人工审批；请核对事实、语言、变量、退订方式。AI 被约束不编造事实，但仍需你负责最终内容。

**Q4：接管后 AI 还会发吗？**
不会。接管会取消未发送任务，且发送前会再次校验状态。

**Q5：客户退订了，我能恢复自动化再发吗？**
不能。`DO_NOT_CONTACT` 需要 admin/owner 删除抑制记录才能解除；请尊重对方意愿。

**Q6：为什么评分和我预期不一样？**
评分是规则分，看"因素"和"排除项"的具体原因；数据缺失会拉低"信息可信度"。补全后再评分。

**Q7：任务一直是"排队中"？**
检查服务端是否 `WORKER_ENABLED=1`、Worker 是否崩溃（日志 `worker crashed`）、是否全局暂停了任务。

**Q8：怎么换模型？**
「系统设置 → AI 模型」保存新的 Provider/API Key →「系统设置 → 数据源」启用 `openai_compatible` →「智能代理 → 测试 Provider」。不必改代码。

**Q9：数据存在哪？**
`server/data/outreach.sqlite`（SQLite，WAL）；上传 `uploads/`；密钥 `secret.key`；备份 `backups/`。全部在你自己的服务器。

**Q10：能多个人一起用吗？**
可以。owner 邀请成员并分配角色；每个人独立账号；数据按工作空间隔离。

**Q11：忘记管理员密码怎么办？**
在服务器执行 `npm run reset-password`（本地脚本，无需邮箱），按提示重置。

**Q12：能导出全部数据吗？**
企业/联系人支持 CSV 导出；完整数据库可直接复制 `outreach.sqlite`（停机或热备）。
