# ZHIRAI 外贸获客平台 · 客户识别与联系规则 v1

整理时间：2026-10-24  
目的：把“客户画像规则”和“通用客户规则”分开，避免把行业规则、联系方式规则、客户状态混在一起。

---

## 一、核心原则

客户画像只回答一个问题：

> 去哪个行业、哪个国家、找什么类型的企业？

它不负责判断：

> 这个企业能不能联系上、联系方式是否完整、是否已经回复。

通用规则负责：

- 有没有官网域名
- 有没有邮箱
- 有没有电话
- 有没有地址
- 有没有在线联系
- 有没有社交账号
- 信息是否有来源、是否可验证
- 是否可以进入潜在客户
- 当前处于什么客户阶段

一句话：

> **画像是方向，联系方式是底线，回复和沟通才是意向。**

---

## 二、客户分级

### 1. 发现池 Discovered

刚搜索到、还没有完成核验的企业。

允许：

- 只有名称
- 只有域名
- 信息不完整

发现池不等于潜在客户，不直接进入外呼。

### 2. 潜在客户 Potential

**必须有官网域名。**

按联系方式完整度分级：

| 等级 | 条件 | 处理 |
| --- | --- | --- |
| A 完整 | 域名 + 邮箱 + 电话 + 地址 + 在线联系/社交 | 优先联系 |
| B 较完整 | 域名 + 邮箱 + 电话（缺地址或在线） | 正常联系 |
| C 部分 | 域名 + 邮箱，或域名 + 电话 | 可联系，但先补全 |
| D 仅官网 | 只有域名 | 低优先，待补全 |
| 不合格 | 没有域名 | 不进入潜在客户 |

### 3. 已联系 / 未回复 Contacted

已经发送开发信或消息，但没有回复。

### 4. 意向客户 Intent

客户已经回复，并且回复内容表示：

- 有兴趣
- 要报价
- 要样品
- 要目录
- 问交期 / 价格
- 要求进一步沟通

意向客户不是靠联系方式评分判断，而是靠真实回复。

### 5. 确认客户 Customer

已经进入报价、样品、订单或成交阶段。

## 三、通用规则（所有行业都适用）

### 3.1 身份规则

必须尽量确认：

- 企业名称
- 官网域名
- 国家/地区
- 企业类型
- 行业
- 来源 URL
- 采集时间

没有官网域名的企业：

- 可以留在发现池
- 不能进入 A/B/C/D 潜在客户
- 不能进入外呼队列

### 3.2 联系方式规则

联系方式分 6 类：

1. 官网域名
2. 邮箱
3. 电话
4. 公司地址
5. 在线联系（表单、在线客服、WhatsApp、即时聊天）
6. 社交/职业平台（LinkedIn、Facebook、Instagram 等）

每个联系方式都必须记录：

- 值
- 来源页面 URL
- 采集时间
- 识别方式（HTML、mailto、tel、图标点击、表单、JSON-LD）
- 置信度

不能编造联系方式。没有识别到就留空。

### 3.3 联系方式识别规则

必须支持：

- `mailto:` 邮箱
- 页面文字邮箱
- `data-email` / `data-mail`
- Cloudflare 加密邮箱
- `name [at] domain [dot] de`
- `tel:` 电话
- 页面文字电话
- `data-phone` / `itemprop="telephone"`
- JSON-LD 邮箱/电话/地址
- Impressum / Kontakt / Contact 页面
- 点击邮箱/电话图标后出现的联系方式
- 在线表单地址
- WhatsApp / 在线聊天链接
- LinkedIn / 社交链接

### 3.4 联系方式评分规则

总分 100：

| 项目 | 分值 |
| --- | --- |
| 官网域名 | 20（必须有） |
| 邮箱 | 25 |
| 电话 | 20 |
| 公司地址 | 15 |
| 在线联系/表单/WhatsApp | 10 |
| 社交/LinkedIn | 5 |
| 信息有来源且可验证 | 5 |

硬规则：

- 没有域名 = 0 分，不进潜在客户
- 只有域名 = 低分，排最后
- 域名 + 邮箱 + 电话 = 中高分
- 域名 + 邮箱 + 电话 + 地址 + 在线联系 = 高分
- 角色邮箱（info@/sales@/service@）可以保留，但标记为 `risky`，不能标记为 `valid`
- 推测邮箱不能标记为有效

### 3.5 去重规则

- 优先按官网域名去重
- 没有域名时按标准化企业名去重
- 软删除企业再次被发现时恢复，不重复创建
- 同一来源重复结果不重复入库

### 3.6 证据规则

每个判断都要有证据：

- 企业类型判断：官网/Impressum/Kontakt 文本
- 进口商/分销商判断：官网业务描述、产品页、About 页
- 联系方式：来源 URL
- ICP 匹配：关键词/行业/国家/产品证据

没有证据时：

- 标记“待核实”
- 不直接写“进口商”
- 不直接写“高意向”

### 3.7 合规规则

- 抑制名单 / 退订
- 不联系 / 已关闭客户
- 发送窗口
- 每日限额
- 人工接管
- 审批后发送
- 默认不自动群发

## 四、客户画像规则（行业相关）

客户画像只决定搜索方向：

- 行业
- 产品
- 目标国家/区域
- 企业类型
- 企业规模
- 采购角色
- 关键词
- 排除词
- 最低相关度

示例：

### 汽配行业画像

- 德国/奥地利/瑞士
- 汽车售后市场
- 进口商/分销商/批发商
- 刹车、滤清器、底盘、热管理

### 建材行业画像

- 德国/法国/荷兰
- 建材进口商/批发商
- 瓷砖、板材、门窗、装饰材料

### 家居行业画像

- 欧洲
- 家居用品分销商/连锁零售
- 家具、装饰、收纳

画像不是写死汽配，行业可以任意配置。

## 五、搜索与页面识别流程

### 5.1 搜索

1. 从客户画像提取全部关键词
2. 每个关键词生成多语言搜索词
3. 调用搜索源（Tavily / Brave / Serper / SearXNG）
4. 收集结果：标题、URL、摘要、来源
5. 按域名去重
6. 过滤黄页、目录站、招聘、社交、新闻

### 5.2 官网识别

对每个候选企业：

1. 打开官网首页
2. 打开 Impressum / Kontakt / Contact / About
3. 等待 JS 加载
4. 点击邮箱/电话/联系图标
5. 读取 `mailto:`、`tel:`、表单、社交链接
6. 记录所有联系方式及来源 URL
7. 识别公司地址
8. 判断企业类型和行业

### 5.3 AI 相关度判断

对每个企业：

- 关键词命中
- 行业命中
- 产品类别命中
- 企业类型命中
- 国家命中

输出：

- 相关度分
- 匹配证据
- 不匹配原因
- 是否进入潜在客户

相关度低的企业不直接进入外呼。

## 六、浏览器 MCP 方案

### 能做什么

- 真正打开官网
- 点击 Kontakt / Impressum
- 点击邮箱、电话图标
- 读取 JS 渲染后的内容
- 读取在线表单、WhatsApp、聊天链接
- 记录地址和社交账号

### 不建议做什么

- 不建议用浏览器自动化直接搜索 Google/Bing
  - 容易被验证码
  - 容易封 IP
  - 违反搜索引擎条款
- 不建议高频批量访问
- 不建议伪装成真实用户绕过限制

### 推荐分工

- 搜索：Tavily / Brave / Serper / SearXNG
- 打开官网、识别联系方式：Playwright 浏览器 worker
- 相关度判断：AI
- 写入和评分：后端规则

### 浏览器 worker 要求

- 一次只处理一个企业
- 每个网站间隔 3–8 秒
- 超时重试
- 失败记录原因
- 不无限重试
- 优先处理官网
- 不把目录站当官网

## 七、评分体系

### 联系方式分（60 分）

- 域名 20
- 邮箱 25
- 电话 20
- 地址 15
- 在线联系/社交 10
- 来源可信 5

### 画像相关分（40 分）

- 行业匹配 15
- 产品/关键词匹配 15
- 国家/区域匹配 10

### 总分

```text
总分 = 联系方式分 + 画像相关分
```

### 硬性门槛

- 没有域名：不进潜在客户
- 联系方式分低于 20：只进发现池
- 相关度低于阈值：不进外呼
- 已回复：进入意向客户，不再只看分数

## 十、结论

客户画像决定“找谁”，通用规则决定“能不能联系、值不值得联系”。

真正的外贸客户不是：

> 搜到一个公司名。

而是：

> 有官网、有业务证据、有联系方式、能发消息、能收到回复。

当前平台已经能完成“搜索和初步联系方式识别”，但还没完成：

- 浏览器级页面识别
- 在线联系识别
- 联系方式完整度评分
- 客户阶段拆分
- AI 行业相关度判断

下一步应优先补这五项，而不是继续堆付费 API。
